Top-k Accuracy Explained

What the top-k metric measures, how we calculate it, and how to read the graph.

1. The problem with the current score

The current score looks at one answer only. The model writes its first answer. We compare that name with the gold label.

The score is "right" or "wrong". There is nothing in between.

But the model has more information than one answer. Before it writes a name, it gives a probability to every possible name. The first answer is the name with the highest probability. The second-best name is also useful.

Example: the gold label is "Appeal to Fear". The model puts "Just in Case Fallacy" first and "Appeal to Fear" second. The current score says "wrong". But the model almost had it.

2. What top-k is

The model ranks all known fallacy names from most likely to least likely.

An example is top-k correct when the gold label is in the first k names of this ranking.

Top-k accuracy is the share of eval examples that are top-k correct.

In this example, the gold label is at rank 2. So the example is wrong at k=1. It is correct at k=2 and at every larger k.

3. Two rules that always hold

  • Top-1 accuracy is almost the same as our strict score. It uses only the best name. A small difference is normal (see section 7).
  • Top-k accuracy never goes down when k becomes larger. A larger k gives the gold label more chances.

At k = 185 (all names), the accuracy is 100%. Every gold label is somewhere in the list.

4. How we calculate the ranking

  1. Collect the 185 fallacy names from the training and eval files. Each name is one candidate.
  2. For each eval example, build the prompt in the same way as in training.
  3. For each candidate, calculate the probability that the model writes exactly Fallacy: <name> followed by a new line. The model gives a probability for each token. We add the log-probabilities of all tokens in the string.
  4. Sort the 185 candidates by this probability. The highest is rank 1.
  5. Find the rank of the gold label. Save it.
  6. After all 135 examples, count how many have a rank of k or better. Divide by 135.

The script is topk.py. It runs one model at a time and saves the ranks in data/topk_<run>.json.

5. How the graph works

  • The x-axis is k.
  • The y-axis is the top-k accuracy.
  • Each line is one run: the untrained baseline, the first run, and runs A to F.

The graph shows two things.

  1. The left end (k=1) is the strict score. It agrees with the numbers we already have.
  2. The slope shows how often the correct name is a near-miss. A line that rises fast between k=1 and k=3 means the model usually has the right name close to the top. A line that rises slowly means the model does not know the right name.

6. Top-k and alias groups

Both methods try to give credit for near-misses. They work in different ways.

Alias groupsTop-k
Who decides what is close?A person (or a classifier) decides.The model decides, with its own ranking.

7. Limits

Top-k is not what a user sees. A user gets one answer. The top-k score is useful to compare models and to find near-misses. It is not the same as the accuracy of the real product.

Short names have an advantage. We add log-probabilities, so a long name has more tokens that can lower its score. This is also how the model writes text.

Top-1 can differ from the strict score by an example or two. The strict score uses greedy decoding. The model picks the best token, one step at a time. Top-1 picks the name with the best probability for the whole name. These can be different names. In our test on run B, the strict score was 100 of 135 (74.1%) and top-1 was 101 of 135 (74.8%).

The baseline is not directly comparable. The untrained model does not know the answer format. We add a format hint to the prompt for this model only, as in the earlier baseline test.

The eval set is small. With 135 examples, differences of 3 to 4 points between runs are inside the noise.
