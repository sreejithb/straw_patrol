Calibration Explained

Why the bot must adjust its confidence numbers before we use them, and how we do it.

1. What we want to build

The bot reads a comment. It then writes one of these messages:

  • "This is A." The bot is sure.
  • "It is mostly A, but it could also be B." The bot is not sure.
  • "No fallacy here." The comment contains no fallacy.

To choose the message, the bot must know how sure it is. We need a number for this. The number is the confidence.

The rule is simple. A high confidence gives one name. A low confidence gives more names.

The rule only works when the confidence number is true. This page explains what "true" means and how we make it true.

2. Where the confidence number comes from

Our model does not give a confidence number directly. It gives a score to each fallacy name. A higher score means the model likes the name more.

We have about 186 names (185 fallacies and "None"). We change the 186 scores into 186 probabilities. A probability is a number from 0 to 1. All 186 probabilities add up to 1. This step is called softmax.

3. What "calibrated" means

A model is calibrated when its confidence is equal to how often it is right.

Take 100 comments. For each one, the model says "I am 80% sure". If the model is calibrated, it is right on about 80 of the 100 comments.

Model saysModel is right onVerdict
"80% sure" on 100 comments80 commentsCalibrated
"95% sure" on 100 comments70 commentsOverconfident. It claims more than it knows.
"50% sure" on 100 comments75 commentsUnderconfident. It claims less than it knows.

The three rows are examples to show the idea. They are not data from our model.

4. Why our model is overconfident

We trained the model to give the correct name. During training, the model sees each example many times. It learns to put almost all of the probability on the name it has seen.

The training loss is the model's average error on the training examples. In runs E and F (10 epochs) it went down to 0.002–0.005. In run H (5 epochs) the last batch had a loss of 0.054. These are very low numbers. They mean the model is nearly sure on the training examples.

New comments are different. On the eval set, the model is right only about 70% to 75% of the time. We expect that the model still puts a very high probability on its first name for most comments. We have not measured this yet. The first step of the plan (section 10) measures it. If the model is not overconfident, calibration will change little, and that is also a useful result.

The danger. Suppose the bot says "This is A" whenever the confidence is above 90%. If the numbers are too high, the bot says "This is A" on comments where it is wrong 3 times in 10. It never shows "could also be B", even when B is the right answer.

The reliability diagram

A reliability diagram shows this problem. The x-axis is the confidence that the model states. The y-axis is how often the model is right at that confidence. A calibrated model stays on the diagonal line.

5. The fix: temperature scaling

The fix is simple and has only one number. This number is called the temperature (T).

Before softmax, we divide every score by T. If T is larger than 1, the probabilities become flatter. The top name keeps its place. Only the confidence changes.

A worked example

Suppose a comment gets these scores. Larger is better.

NameScoreProbability at T = 1Probability at T = 3
A−194.6%64.2%
B−44.7%23.6%
C−60.6%12.1%

The scores are an example. The probabilities follow from them by the softmax formula (for three names only).

With the raw numbers, the bot would write "This is A" (94.6% sure). With the calibrated numbers, the bot sees 64.2% for A and 23.6% for B. It writes "It is mostly A, but it could also be B."

6. How we find the right temperature

We do not guess T. We measure it on data. The method has five steps.

  1. Take a set of comments for which we know the correct answer. This is the calibration set.
  2. Run the model on each comment. Keep the 186 scores.
  3. Try many values of T, for example 0.5, 1, 1.5, 2, 3, 4.
  4. For each T, calculate how well the probabilities match the correct answers. We use the log loss. It is low when the model gives a high probability to the correct name, and high when the model is confidently wrong.
  5. Keep the T with the lowest log loss. This is the temperature that the bot uses.

The whole fit takes less than one second. It does not change the model weights.

How we check the result

We use the expected calibration error (ECE). It is the average gap between the stated confidence and the real hit rate. Think of the distance of the points in Figure 2 from the diagonal. A lower ECE is better. We calculate the ECE before and after calibration.

7. Why we need a separate calibration set

We cannot use the training data to find T. The model has seen these examples. It looks perfect on them, so the fit would pick T = 1 and nothing would change.

We also cannot use the test (eval) set. We need the test set to measure the final result. If we tune T on the same comments, the final numbers look better than they are.

Today we have the train set and the test set. We have no calibration set. This is why we need to make one.

8. From probabilities to the message

After calibration, the bot uses a simple rule. It shows the smallest group of names whose probabilities add up to about 90%. We tune the 90% on the calibration set so that the correct answer is inside the group about 9 times in 10.

How the alias groups help

Some names in the group may mean the same thing. For example, "Causal Reductionism" and "Insignificant Cause" describe nearly the same error. The bot must not show them as two different doubts. It writes "also called", or "closely related", for these names. The alias file tells the bot which names are close.

9. What calibration cannot do

It cannot make a wrong model right. The model keeps the same top name. We only change how sure it sounds. The accuracy stays at about 70% to 75%.

It trusts the calibration set. If the calibration comments look different from real X comments, the numbers will be wrong on real comments. Real comments are longer and less clean than our generated text. We must test on real-style comments. We plan to add some.

A small set gives noisy numbers. With 100 comments, the hit rate at each confidence level has an error of a few points. We need at least a few hundred comments. We can add more over time.

One T may not fit every name. The model could be overconfident on some fallacies and not on others. One number cannot fix this. We will check by name on the calibration set. If the problem is large, we can add a second step.

10. The plan

  1. Change topk.py so that it saves the top names and their scores for each comment.
  2. Make the calibration set: about 250 new fallacy examples and 100 "None" examples, plus some real-style comments that you choose or write. We use new random seeds, so the set is different from the training data.
  3. Run the model on the calibration set. Find the temperature T.
  4. Measure the ECE and the coverage before and after.
  5. Tune the 90% rule.
  6. Check the final result on the test set (eval.jsonl and eval_none.jsonl).
  7. Write straw_bot.py. It reads one comment and writes the message.
