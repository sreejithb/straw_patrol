Option 1: Alias Scoring

A fairer way to score the model. This page says what it is, why we need it, and what I will do.

1. The problem

Today, the score counts an answer as correct only when the name is the same as the gold label. The comparison is exact.

But many fallacies in the book are almost the same. Their definitions overlap. Some are only different names for one error.

Example: the gold label is "Insignificant Cause". The model says "Causal Reductionism". Both names describe the same error. The score counts this answer as wrong.

I read the 12 examples that all six runs missed. In 9 of them, the model gave a defensible answer. So the real accuracy is higher than the score shows.

2. What option 1 is

An alias group is a set of fallacy names that describe the same error, or nearly the same error.

With option 1, an answer is correct when it names any fallacy in the same group as the gold label.

The model does not change. The training data does not change. Only the scoring changes.

3. Where the groups come from

Your review step already did part of this work. For each training example, a classifier chose the best-matching fallacy from the full list. It also gave an also_fits list of other names that fit.

These lists are saved in data/generated/review_cache.jsonl. They show which fallacies the classifier often confuses.

I will count how often each pair of names appears together. Pairs that appear often are candidates for a group.

4. The plan

  1. Read the also_fits lists from the review cache.
  2. Count how often each pair of fallacies appears together.
  3. Add the pairs from my review of the 12 hard cases, such as Insignificant Cause and Causal Reductionism.
  4. Write a draft file with the groups: data/alias_groups.json.
  5. Show you the draft. You approve, remove, or change each group.
  6. Add a new scoring mode to evaluate.py. It reads the group file and gives a second score.
  7. Score the saved predictions of all six runs again. No new model run is needed.
  8. Report the strict score and the alias score side by side.

5. What stays the same

  • The strict score stays in the output. We can still compare with the old numbers.
  • The saved predictions stay as they are. The new score only reads them.
  • The eval set eval.jsonl does not change.

6. Cost and time

  • No API calls are necessary. The data is already on your computer.
  • No Colab run is necessary.
  • The work takes a few minutes. Your review of the groups takes the most time.

7. Risks

Groups can be too wide. If two names that are different go in one group, the score goes up for the wrong reason. This is why you approve each group.

The new score is not a model improvement. The model gives the same answers. The score only shows more clearly how good they were.

The model sometimes makes up names. Examples: "Fallacy of spite" and "Appeal to Presentation". These names are not in the book. An alias group cannot cover a name that does not exist. I will list these names separately.
